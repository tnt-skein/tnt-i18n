# Переводы

`tnt-i18n` — строки по языкам: поиск по ключу с подстановками, формы
слова при числе по правилу языка, язык запроса по заголовку
`Accept-Language` и сверка переводов с языком по умолчанию.

```lua
local i18n = require('tnt.i18n')

local lang = i18n.new({
    locale = 'ru',                                   -- язык по умолчанию
    messages = {
        ru = {
            customer = { not_found = 'Клиента №{id} нет' },
            nodes = { '{count} узел', '{count} узла', '{count} узлов' },
        },
        en = {
            customer = { not_found = 'Customer {id} not found' },
            nodes = { '{count} node', '{count} nodes' },
        },
    },
})

lang:get('customer.not_found', { id = 7 })         --> 'Клиента №7 нет'
lang:get('customer.not_found', { id = 7 }, 'en')   --> 'Customer 7 not found'
lang:choice('nodes', 5)                            --> '5 узлов'
lang:choice('nodes', 1, nil, 'en')                 --> '1 node'
```

Зависит от [`tnt-str`](https://github.com/tnt-skein/tnt-str)
(согласование слова с числом по-русски),
[`tnt-context`](https://github.com/tnt-skein/tnt-context) (язык запроса)
и [`tnt-must`](https://github.com/tnt-skein/tnt-must) (проверки
аргументов). Файлов пакет не читает: строки приходят таблицами, а откуда
их взять — из файлов, из базы, из настроек, — решает приложение.

## Зачем пакет

Строка для человека, написанная прямо в коде, переводу не поддаётся:
её не найти по ключу, а склеенную по месту — `'Клиента №' .. id .. ' нет'`
— не перевести даже найдя, потому что в другом языке слова встанут
иначе. Поэтому строка берётся по ключу, а значения встают в неё
по именам: `{id}` переживает перевод, где предложение построено
по-другому.

Второе — число. «5 узел» пишет всякий, кто согласует слово с числом
одним правилом «один — много»: у русского форм три, и одиннадцать —
четырнадцать не слушаются последней цифры. Правило согласования живёт
в `tnt-str` (`str.plural_form`, раздел «Согласование с числом» его
документа): строка, собранная в коде, и строка перевода считают формы
одним правилом, а здесь только выбирается, чьё правило применить.

Третье — язык запроса. Его выбирают один раз, на входе, а нужен он
в глубине: обработчику, шаблону, проверке формы. Передавать его
аргументом через все слои — менять подпись каждой функции ради значения,
которое она сама не читает. Поэтому слой кладёт язык в контекст файбера
(`tnt-context`, ключ `locale`), а `get` и `choice` берут его оттуда.

## Как пользоваться

### Что умеет фасад

| Вызов | Что делает |
|---|---|
| `i18n.new(opts)` | собирает переводчик; негодные строки — исключение на строке вызывающего |
| `i18n.explain(opts)` | то же без броска: что не так, словами, либо `nil` |
| `i18n.normalize(tag)` | метка языка по форме: `'EN_gb'` → `'en-GB'`; не метка — `nil` |
| `i18n.chain(tag)` | цепочка отступления: `'zh-Hant-TW'` → `zh-Hant-TW`, `zh-Hant`, `zh` |
| `i18n.parse(header)` | языки `Accept-Language` по убыванию веса |
| `i18n.negotiate(header, available, default)` | лучший из объявленных языков для заголовка |
| `i18n.CONTEXT_KEY` | ключ контекста с языком запроса, `'locale'` |
| `i18n.REQUEST_KEY` | поле запроса, куда слой кладёт язык запроса, `'locale'` |
| `i18n.PLURALS` | встроенные правила множественного числа по языку |

У переводчика:

| Вызов | Что делает |
|---|---|
| `lang:get(key, params, tag)` | строка по ключу с подстановками |
| `lang:choice(key, count, params, tag)` | форма строки при числе; число встаёт в `{count}` |
| `lang:has(key, tag)` | есть ли строка в языке — без языка по умолчанию |
| `lang:locale()` | язык запроса: из контекста либо по умолчанию |
| `lang:locales()` | объявленные языки по алфавиту |
| `lang:negotiate(header)` | лучший объявленный язык для `Accept-Language` |
| `lang:diff(tag)` | сверка языка с языком по умолчанию |
| `lang:layer(opts)` | слой языка запроса для роутера |

Последний аргумент `tag` у `get`, `choice` и `has` необязателен: без него
говорят на языке запроса.

### Строки

Строки пишут деревом разделов, а ищут по полному ключу через точку.
Ключ можно записать и целиком — это тот же ключ:

```lua
local lang = i18n.new({
    locale = 'ru',
    messages = {
        ru = {
            home = { title = 'Главная', menu = { about = 'О нас' } },
            ['customer.saved'] = 'Сохранено',
        },
    },
})

lang:get('home.menu.about')   --> 'О нас'
lang:get('customer.saved')    --> 'Сохранено'
```

Значение — строка либо список форм при числе. Всё прочее — число,
логическое, список с чем-то кроме строк — отказ при сборке, как и ключ,
заданный дважды (`home = { title = … }` рядом с `['home.title']`).

Подстановка — `{имя}`. Подстановка, для которой значения не передали,
остаётся в строке как есть: «Клиента №{id} нет» сразу говорит, что
забыли `id`, а «Клиента № нет» выглядит законченной фразой и доживает
до выкладки.

```lua
lang:get('customer.not_found', { id = 7 })   --> 'Клиента №7 нет'
lang:get('customer.not_found')               --> 'Клиента №{id} нет'
```

### Где ищется строка

Сначала в языке, потом в укороченной метке, потом в языке по умолчанию:

```lua
local lang = i18n.new({
    locale = 'ru',
    messages = {
        ru = { home = { title = 'Главная' }, saved = 'Сохранено' },
        en = { home = { title = 'Home' }, bye = 'Bye' },
        ['en-GB'] = { home = { title = 'Home page' } },
    },
})

lang:get('home.title', nil, 'en-GB')   --> 'Home page'
lang:get('bye', nil, 'en-GB')          --> 'Bye': британский берёт английское
lang:get('saved', nil, 'en')           --> 'Сохранено': пусть по-русски, чем никак
lang:get('no.such.key')                --> 'no.such.key'
```

Ключ, которого нет нигде, возвращается сам: `no.such.key` на странице
сразу видно. Полноту переводов сверяет `diff` — в проверках приложения,
а не глазами посетителя.

### Формы при числе

Строка со множественным числом — список форм в порядке правила языка:
у русского три («узел», «узла», «узлов»), у английского две («node»,
«nodes»). Число форм сверяется при сборке, а не на первом запросе:

```lua
local lang = i18n.new({
    locale = 'ru',
    messages = {
        ru = { nodes = { '{count} узел', '{count} узла', '{count} узлов' } },
        en = { nodes = { '{count} node', '{count} nodes' } },
    },
})

lang:choice('nodes', 21)              --> '21 узел'
lang:choice('nodes', 12)              --> '12 узлов'
lang:choice('nodes', 1.5)             --> '1.5 узла'
lang:choice('nodes', 0, nil, 'en')    --> '0 nodes'
lang:choice('nodes', 1.5, { count = '1,5' })   --> '1,5 узла'
```

Число встаёт в `{count}` само, если своего `count` в подстановках нет;
десятичную запятую пишут своим `count`.

Встроенных правил четыре: `ru`, `uk` и `be` — правило `tnt-str`
(украинский и белорусский согласуют слово с числом так же), `en` —
единица и всё остальное. Прочим языкам правило задают настройкой
`plurals`: число форм и функция, которая отдаёт номер формы. Правило
служит и языку с областью (`fr` — и `fr-CA`), а заданное для
встроенного языка заменяет встроенное:

```lua
local lang = i18n.new({
    locale = 'fr',
    messages = { fr = { books = { '{count} livre', '{count} livres' } } },
    plurals = {
        fr = { forms = 2, form = function(count) return count < 2 and 1 or 2 end },
    },
})

lang:choice('books', 1.5)   --> '1.5 livre'
lang:choice('books', 2)     --> '2 livres'
```

Угадывать правило по похожему языку пакет не берётся: «1,5 livres» там,
где нужно «1,5 livre», — ровно такая ошибка.

Форма выбирается правилом того языка, где строка нашлась: строка,
взятая из языка по умолчанию, согласуется с числом по его правилу,
а не по правилу языка запроса.

### Язык запроса

`lang:layer()` — слой по договору
[`tnt-middleware`](https://github.com/tnt-skein/tnt-middleware): функция
от запроса и остатка цепочки. Он выбирает язык и кладёт его в контекст
на весь остаток цепочки.

```lua
local lang = i18n.new({
    locale = 'ru',
    messages = { ru = { hello = 'Привет' }, en = { hello = 'Hello' } },
})
local layer = lang:layer()

local request = { headers = { ['accept-language'] = 'en-US,en;q=0.9' } }
local response = layer(request, function()
    return { status = 200, body = lang:get('hello') }
end)
--> { status = 200, body = 'Hello',
-->   headers = { ['content-language'] = 'en', vary = 'Accept-Language' } }
request.locale   --> 'en'
```

Язык выбирается так:

1. Явный выбор человека, если его назвала функция `from` — из куки,
   сессии, профиля. Названный и объявленный язык выигрывает у заголовка,
   а негодный либо необъявленный просто не выбирается:

   ```lua
   local cookie = require('tnt.cookie')

   local chosen = lang:layer({
       from = function(request)
           return cookie.parse(request.headers['cookie']).locale
       end,
   })
   ```

   Куку здесь разбирает [`tnt-cookie`](https://github.com/tnt-skein/tnt-cookie);
   зависимостью пакета он не объявлен — `from` может брать язык откуда
   угодно.

2. Заголовок `Accept-Language`: языки по убыванию веса, у каждого —
   поиск по цепочке (RFC 4647, §3.4). `en-GB` находит строки `en`,
   а `en` строк `en-GB` не находит: язык без области говорит «любой
   английский», и выбрать за человека британский было бы догадкой.
   Поэтому язык, общий для всех областей, объявляют без области.
   `*` значит «любой» — это язык по умолчанию.
3. Язык по умолчанию.

Ответу-таблице слой ставит `Content-Language`, если его не поставил
обработчик, и дописывает `Accept-Language` в `Vary`: кэш обязан хранить
такой ответ по языку, иначе второй посетитель получит страницу на языке
первого. Отказ парой `nil, err` проходит как есть.

Выбранный язык слой кладёт и в сам запрос — полем `locale`
(`i18n.REQUEST_KEY`), если запрос таблица. Контекст кончается вместе
со слоем, а отказ парой проходит его насквозь, и рисует такой отказ
обработчик отказов уже снаружи, где контекста с языком нет. Запрос
доезжает до обработчика отказов вторым аргументом, и слово отказа
находит язык в нём: так его переводит пакет отказов `tnt-error`
(настройка `translate`), он же ставит такому ответу `Content-Language`
и `Vary`.

Заголовок пишет клиент, и отказа по нему нет: негодная запись
пропускается, вес — от нуля до единицы, не больше трёх знаков после
точки, `q=0` значит «не подходит». Заголовок длиннее 1024 байт
не читается вовсе, а из языков берутся первые шестнадцать:

```lua
i18n.parse('en-GB,en;q=0.8,ru;q=0.9')
--> { { tag = 'en-GB', q = 1 }, { tag = 'ru', q = 0.9 }, { tag = 'en', q = 0.8 } }
i18n.negotiate('de,ru;q=0.5', { ru = true, en = true }, 'en')   --> 'ru'
```

Вне запроса — фоновая работа, консоль, проверка — языка в контексте нет,
и говорят на языке по умолчанию; нужный язык там называют аргументом
либо кладут в контекст сами:

```lua
local context = require('tnt.context')

context.run({ [i18n.CONTEXT_KEY] = 'en' }, function()
    return lang:get('hello')   --> 'Hello'
end)
```

Метку в контексте пакет записывает по форме: язык строчными,
письменность с прописной, область прописными — `sr-Latn-RS`. Негодная
метка в контексте запрос не роняет: говорят на языке по умолчанию.
В журнал язык не пишется и за границу процесса не едет — соседний узел
отвечает данными, а язык выбирает тот, кто рисует.

### Сверка переводов

`lang:diff(tag)` сверяет язык с языком по умолчанию: каких строк
не хватает, какие лишние и у каких разошлись подстановки. Место ей —
в проверках приложения:

```lua
local lang = i18n.new({
    locale = 'ru',
    messages = {
        ru = { a = 'А {x}', b = 'Б', c = 'В {n}' },
        en = { a = 'A {x}', c = 'C', z = 'Z' },
    },
})

lang:diff('en')   --> { missing = { 'b' }, extra = { 'z' }, mismatched = { 'c' } }
```

Подстановки у форм при числе сверяются всеми формами вместе:
`{ 'one', '{count} nodes' }` и `{ '{count} узел', … }` сходятся.

### Отказы при сборке

Строки пишет программист, и опечатка в них — исключение при сборке,
на строке вызывающего `new`, а не отказ на первом запросе:

```
язык по умолчанию «RU» записан не по форме: пишите ru
языка по умолчанию de среди строк нет: есть en, ru
строки языка ru: home.title — строка либо список форм, а не число
строки языка ru: ключ home.title задан дважды
строка nodes языка ru: форм 2, а у языка их 3
строка nodes языка fr — формы при числе, а правила множественного числа у языка нет: задайте его настройкой plurals
строка nodes — формы при числе в языке ru и одна строка в языке en
```

`i18n.explain(opts)` отдаёт тот же текст без броска — для того, кто
бросает сам и по-своему: раскладка приложения показывает его оператору
без места в коде.

Ошибки вызова — тоже исключения: негодный ключ, язык, который не метка,
`get` строки с формами (её берёт `choice`) и `choice` строки без форм
(её берёт `get`), бесконечность вместо числа, правило, отдавшее номер
вне своих форм.

## Чем пришлось поступиться

**Ключ, которого нет, возвращается сам, а не отказом.** Строка нужна
странице, и отказ на каждом ненайденном ключе уронил бы страницу из-за
недописанного перевода. Видимый ключ на странице и `diff` в проверках
ловят то же самое раньше посетителя.

**Язык по умолчанию — последняя надежда, а не отказ.** Строка, которой
нет в языке запроса, уходит на языке по умолчанию: посетитель прочтёт
пусть по-русски, но прочтёт. Кому это не годится, сверяет `diff`.

**Поиск не расширяет язык до области.** `Accept-Language: pt` не находит
строк `pt-BR`: выбрать область за человека — догадка. Язык, общий для
всех областей, объявляют без области.

**Число подставляется `tostring`.** «1.5», а не «1,5»: вид числа —
забота приложения, и десятичную запятую пишут своим `count`.

**Отказ за слоем говорит на языке запроса, только если его переводят.**
Слой отказа не рисует и об отказах не знает: пара `nil, err` проходит
его насквозь, и заголовков ей слой не ставит — ставить их некуда, ответа
ещё нет. Язык такому отказу остаётся в запросе, а слово и заголовки
ставит тот, кто отказ рисует, — `tnt-error` по настройке `translate`.
Обработчик отказов без перевода отвечает по-прежнему на своём языке.

**Правила есть только у четырёх языков.** Остальным их задают настройкой:
правило чужого языка, написанное по догадке, ошибается молча.

## Проверки

Проверки лежат в `test/` и идут на luatest: `make test`. Язык запроса
лежит в контексте настоящего файбера, двойников нет. Отказы сборки
и вызова сверяются текстом целиком, а место броска — файлом
вызывающего, а не строкой внутри пакета.

- `locale_test.lua` — запись метки, цепочка, разбор заголовка, пределы,
  выбор языка.
- `messages_test.lua` — дерево в ключи, отказы разбора, подстановки.
- `translator_test.lua` — поиск и отступление, формы при числе
  и правила, язык из контекста, сверка, отказы настроек и вызова.
- `layer_test.lua` — выбор языка слоем, явный выбор, заголовки ответа,
  язык в запросе, отказ насквозь.

Проверок — 51; покрытие строк — 100 %, убитых мутантов — 100 %
(347 мутантов в пяти модулях; фасад `tnt/i18n.lua` мутировать
нечем — в нём ни развилок, ни чисел).
